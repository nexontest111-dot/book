# 골프·사회인야구 부킹 서비스 요구사항 초안

작성일: 2026-10-08
상태: 사용자 답변에 기반한 요구사항 초안. 양측 결제 후 최종 확정 정책은 승인됨. 기술 스택과 그 외 미정 정책은 확정하지 않음.

## 1. 확인된 방향

- PC·모바일 브라우저에서 이용하는 반응형 웹을 제공한다. 같은 계정과 예약 데이터를 사용한다.
- 골프 팀 예약·개인 조인, 사회인야구 구장 대관·경기 매칭을 모두 제공한다는 의미로 해석했다. 세부 상품 범위는 추가 확인한다.
- 시설이 예약 가능한 슬롯을 공개한다. 이용자는 공개 슬롯을 기준으로 시간과 조건을 협의하고, 약속과 시설 예약을 서비스 안에서 함께 처리한다.
- 예약은 양측의 동의를 거쳐 확정한다. 상품별 동의 주체와 시설 슬롯 확정 권한의 관계는 확인 중이다.
- 이용자는 공개 슬롯을 선택하고 대체 슬롯을 제안할 수 있다. 협의로 새로운 시간대를 만들 경우 시설 권한자의 확인을 받아야 한다.
- 초기 수익 모델은 부킹 수수료다. 양측 조건 합의 시 경기 참가자 양측에 동일하게 청구하고, 양측 납부가 완료되면 최종 예약을 확정한다. 시설 운영자는 이 양측에 포함되지 않는다. 개인·팀별 청구 단위, 동일 금액인지 동일 요율인지, 수수료 금액과 확정 후 취소·환불 기준은 미정이다.
- 결제 대기는 초기 기준 30분이다. 유효한 시설 슬롯을 임시 점유한 뒤 결제를 요청한다. 만료 시 슬롯을 해제하고, 납부자의 수수료 전액 결제 취소를 요청한다.
- 시설 제휴를 추가할 수 있는 구조가 필요하다. 초기 제휴 계약 방식과 공급 확보 방식은 미정이다.

## 2. 사용자와 권한

| 역할 | 범위 |
| --- | --- |
| 회원 | 검색, 자신의 예약 문의·협의·확정·취소 요청 및 내역 확인 |
| 모집자·팀 대표 | 자신의 조인·경기 모집, 참가 신청 응대, 참가 조건 협의 |
| 시설 운영자 | 담당 시설의 정보·일정·가격 및 예약 응대 |
| 서비스 관리자 | 시설 검수, 계정·운영 정책 관리, 분쟁 및 수수료 처리 |

한 계정이 여러 역할을 가질 수 있다. 시설 운영자 권한은 담당 시설에 한정하고, 모집자는 자신의 모집 건만 관리한다. 채팅 참여와 예약 조회 권한은 서버에서 검증한다.

## 3. 상품별 흐름과 차이

| 상품 | 협의할 조건 | 확정 전 필요한 확인 |
| --- | --- | --- |
| 골프 팀 예약 | 코스, 날짜, 티타임, 인원, 비용, 카트·캐디 조건 | 시설의 티타임 확보 및 예약 조건 동의 |
| 골프 개인 조인 | 기존 라운드의 참가 인원, 시간, 참가 조건과 비용 | 모집자 승인과 남은 참가 자리 |
| 야구장 대관 | 구장, 시작·종료 시간, 조명 등 옵션과 비용 | 구장 이용 가능 여부와 시간 겹침 |
| 야구 경기 매칭 | 상대팀, 경기 시간, 장소, 비용 분담 | 양 팀 동의. 구장 예약 여부는 별도 확인 |

경기 상대팀 합의와 구장 확보를 각각 기록한다. 개인 조인 참가 확정과 골프장 예약 확보도 각각 기록한다. 아직 확보되지 않은 시설을 이용 확정으로 표시하지 않는다.

## 4. 협의와 확정 흐름

1. 시설 운영자가 날짜·시간·판매 수량·요금·옵션이 있는 예약 슬롯을 공개한다.
2. 이용자가 공개 슬롯 또는 슬롯에 연결된 조인·경기 모집을 선택하고 인원 및 조건을 제출한다. 상대방은 제안을 수락하거나 이용 가능한 대체 슬롯과 조건을 제안한다.
3. 양측은 서비스 내부 메시지에서 협의한다. 예약에 영향을 주는 시간·가격·옵션은 별도의 구조화된 제안으로 기록한다.
4. 최신 제안의 동일한 버전에 양측이 동의한다. 조건을 변경하면 이전 동의는 효력을 잃고 다시 동의해야 한다.
5. 서버가 권한, 최신 슬롯 상태, 시설 확보 상태와 예약 수량·시간 충돌을 확인하고 슬롯을 임시 점유한다. 경기·조인 약속과 시설 예약의 연결을 기록한다.
6. 같은 청구 기준으로 두 당사자의 수수료 청구를 함께 생성한다. 초기 결제 기한은 30분이며 양측에 동일한 기한을 표시한다.
7. 양측 납부와 유효한 슬롯 점유를 서버에서 확인한 뒤 최종 예약을 확정한다. 반복 요청은 중복 확정·청구를 만들지 않는다.
8. 만료 시 슬롯을 해제하고 납부한 수수료의 전액 결제 취소를 요청한다. 늦게 도착한 결제 성공은 예약을 되살리지 않고 취소 처리한다.
9. 확정된 조건과 당사자별 청구 내역을 보관하고 PC·모바일 브라우저에 동일한 결과를 보여준다.

결제와 최종 확정의 관계는 사용자 승인 정책이다. 상품별 동의 주체와 시설 점유 방식은 상세 설계에서 구체화한다. 채팅 메시지만으로 예약 확정 처리하지 않는다.

## 5. 상태 설계 초안

- 문의·협의: 접수 → 협의 중 → 조건 합의. 종료 사유는 철회·거절·만료로 기록한다.
- 예약: 협의 중 → 결제 대기 → 확정 → 이용 완료. 결제 대기의 만료, 취소 요청과 취소 완료를 구분한다.
- 수수료: 청구 전 → 청구·납부 대기 → 납부 완료. 각 당사자의 납부와 환불 요청·처리 상태를 별도로 기록한다. 기한 만료 시 납부 금액은 전액 취소 요청한다.
- 모집 참가: 신청 → 협의 또는 승인 대기 → 참가 확정. 철회·거절·취소를 별도로 기록한다.

협의 중에는 슬롯을 점유하지 않고, 양측 합의 후 결제 대기에 진입할 때 임시 점유한다. 공개 슬롯에 다른 문의가 있더라도 자원을 선점한 결제 대기 또는 확정 예약과 충돌할 수 없다. 동의 후에도 최종 확정 전에 서버에서 슬롯을 다시 확인한다. 변경 요청은 원래 확정 예약과 구분해 처리하고, 새 조건을 확보한 뒤 기존 자원을 해제한다.

## 6. MVP 제안과 단계별 완료 조건

### 단계 1: 슬롯 공개·상품 탐색·문의

네 가지 상품을 노출하고 회원·시설·모집 정보를 관리한다. 시설 운영자가 슬롯을 공개하고, 이용자가 실제 슬롯을 선택해 조건을 제안하며 자신의 내역을 조회할 수 있으면 완료한다.

### 단계 2: 협의·확정

서비스 내부 메시지, 대체 슬롯·조건 제안, 최신 조건 동의, 시설 확보 확인, 임시 점유와 양측 수수료 청구를 구현한다. PC·모바일 브라우저에서 동일한 제안과 결제 기한을 확인할 수 있으면 완료한다.

### 단계 3: 종목별 참가·매칭

골프 조인 인원과 야구 상대팀 신청·승인을 관리한다. 참가 수량과 경기 동의 상태가 시설 예약 상태와 함께 정확히 표시되면 완료한다.

### 단계 4: 수수료·취소 및 운영

온라인 수수료 결제, 양측 납부 후 확정, 기한 만료 및 전액 취소, 관리자 이력 조회를 구현한다. PG는 미정이다. 확정 이후 취소·환불은 별도 승인된 정책을 적용한다. 실제 예약 확정 기능의 출시는 이 단계의 결제 처리를 포함해야 한다.

리뷰·쿠폰·고급 통계·자동 정산·외부 시설 시스템 연동은 후속 범위로 제안한다. 실제 출시 범위는 정책과 일정 확인 후 조정한다.

## 7. 화면 목록 초안

- 회원: 홈, 상품 검색, 시설·상품 상세 및 공개 슬롯, 예약 요청, 협의 내역, 조건 확인, 예약·수수료 내역, 모집·참가 관리, 계정 관리
- 시설 운영자: 공개 슬롯·일정 관리, 문의 목록, 협의 상세, 시설·요금 관리, 확정 예약, 해당 시 수수료 내역
- 관리자: 시설·운영자 검수, 회원 관리, 문의·예약 조회, 수수료·분쟁 처리, 공지·정책 관리

## 8. 초기 데이터 모델 후보

- 계정, 역할, 시설 운영 권한
- 시설, 골프 코스, 이용 자원, 공개 슬롯, 일정·이용 불가 시간
- 상품, 모집, 팀, 참가 신청
- 문의, 대화 참여자, 메시지, 조건 제안 버전, 제안 동의
- 예약, 예약 자원 점유, 확정 조건 기록, 시설 예약과 조인·경기 약속 연결
- 당사자별 수수료 청구, 적용 정책 기록, 납부 기록, 취소·환불 요청
- 운영 변경 이력

팀원과 선수의 개인정보는 기능에 필요한 범위로 제한한다. 카드 정보는 직접 저장하지 않고, 온라인 결제 도입 시 결제 제공자의 식별자와 처리 결과를 기록한다.

## 9. 동시 요청과 운영 데이터 보호

- 최종 확정 시 데이터베이스 트랜잭션과 상품별 충돌 제약으로 중복을 막는다.
- 골프 티타임은 상품의 판매 단위와 수량을 확인하고, 야구 대관은 시간 구간 겹침을 확인한다.
- 반복 요청은 같은 작업 식별자로 처리해 확정이나 수수료 청구가 중복 실행되지 않도록 한다.
- 양측 청구는 같은 확정 건과 정책 버전을 기준으로 생성한다. 온라인 납부를 도입하면 당사자별 결제 실패·재시도와 한쪽만 납부한 상황을 처리한다.
- 외부 시설의 실제 재고는 내부 예약만으로 보장할 수 없다. 확인한 주체와 시점을 기록하고 운영 절차를 정한다.
- 확정 조건, 동의, 관리자 조치와 수수료 처리 이력을 남긴다.
- 개인정보 조회 권한과 보관·삭제 정책, 운영 데이터 백업·복구 계획을 상세 설계에서 정한다.

## 10. 다음 결정과 산출물

양측 결제 후 최종 확정 정책과 초기 30분 결제 대기는 승인됐다. 양측은 경기 참가자이며 시설 운영자가 아니다. 개인·팀별 청구 단위, 상대방 없는 단독 대관·골프 팀 예약의 수수료 적용 방식은 추가로 정한다.

추가 미정: 동일 금액 또는 동일 요율 및 수수료 액수, 출시 지역·일정·예산, 제휴 시설 확보, 로그인 방식, 알림 채널, 확정 후 취소·우천·분쟁 정책, 시설별 점유 가능 시간 및 협의 만료, 외부 연동.

다음 산출물: 답변을 반영한 요구사항 확정본, 화면 흐름, 상품별 예약 상태 전이, 반응형 웹 기술 선택지 비교, 데이터·API 설계, 파일별 구현 계획과 완료 조건.

## 11. 현재 작업 기록

프로젝트 폴더는 비어 있었고 기존 코드 및 AGENTS.md는 발견되지 않았다. 모바일 브라우저 제공, 시설 슬롯 공개, 약속·예약 일원화, 경기 참가자 양측 동일 수수료 청구를 반영했다. 사용자 승인에 따라 양측 결제 후 최종 확정과 초기 30분 결제 대기를 채택했다. 상세 화면·상태·데이터·API 설계는 booking-design.md에 기록했다. 기술 스택 선택, 코드 구현, 테스트·빌드·배포는 진행하지 않았다.
