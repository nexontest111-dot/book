# 참가자 양측 부킹 수수료: 결제 정책 제안

작성일: 2026-10-08
상태: 2026-10-08 사용자 승인. 양측 결제 후 최종 확정 정책을 채택함. 확정 이후의 취소·환불 세부 정책은 미정.

## 확인된 사업 방향

시설의 공개 슬롯을 기준으로 참가자 양측이 시간과 조건에 동의한다. 수수료는 시설이 아니라 경기 참가자 양측에 동일하게 청구한다. 초기 온라인 결제 대상은 플랫폼 부킹 수수료로 가정하고, 시설 이용료의 결제·정산 포함 여부는 별도로 정한다.

## 공식 서비스 사례

1. Playtomic 공개 경기: 참가자는 자신의 자리를 온라인 결제한다. 인원이 충족되지 않으면 자동 취소·환불한다. 공개 경기와 사적 시설 예약의 책임·결제 규칙을 구분한다.
   출처: https://playerhelp.playtomic.com/hc/en-gb/articles/19831958258193-Private-Bookings-vs-Open-Matches
2. Playtomic 사적 예약의 분할 결제: 대표 예약자가 자기 몫을 먼저 내고, 다른 참가자의 미납분은 저장 카드·사전 승인·채무 방식 등으로 보장한다. 일부 방식에서는 경기 종료 후 2시간까지 납부를 허용하지만 대표자가 미납분을 책임진다.
   출처: https://helpmanager.playtomic.com/hc/en-gb/articles/20535331224721-Split-Payment-vs-Single-payment
3. Playtomic 공개 경기: 코트 확보와 참가 인원 충족을 별도로 관리한다. 자동 취소 등 해당 안내의 사유로 취소되면 서비스 수수료를 포함해 원 결제수단으로 환불한다.
   출처: https://helpmanager.playtomic.com/hc/en-gb/articles/20535128515601-How-to-cancel-an-Open-Match
4. 국내 결제 구현 참고: 토스페이먼츠는 전체·부분 결제 취소 API를 제공한다. 실제 환불 소요시간은 결제수단과 매입 상태에 따라 다르므로 취소 처리와 환불 완료를 구분해야 한다.
   출처: https://docs.tosspayments.com/guides/v2/cancel-payment

이 사례들은 스포츠 서비스 전체의 통계나 국내 시장의 표준을 입증하지 않는다. 시설비 분할 결제 사례와 본 서비스의 참가자 양측 부킹 수수료는 금액의 성격이 다르다.

## 대안 비교

| 방식 | 장점 | 운영 부담 |
| --- | --- | --- |
| 양측 결제 후 최종 확정 | 미수금과 미납 상태의 확정 예약을 줄임 | 결제 제한시간·슬롯 임시 점유·한쪽 결제 환불 처리 필요 |
| 예약 확정 후 기한 내 납부 | 협의 직후 확정 가능 | 미수금 관리 및 이미 확정된 예약의 미납 처리 필요 |
| 예약 확정 후 보증 수단으로 수금 | 먼저 확정하고 미납 회수 가능 | 보증자 책임과 동의, 결제수단 지원, 결제 실패 처리 필요 |

## 승인된 MVP 정책: 조건 합의 후 양측 결제, 최종 예약 확정

1. 협의 중에는 결제를 요청하지 않는다.
2. 양측이 같은 버전의 시간·시설·비용·옵션에 동의한다.
3. 서버가 시설 슬롯을 확보할 수 있는지 확인하고, 가능한 경우 제한시간 동안 임시 점유한다.
4. 양측에 같은 기준의 수수료를 각각 청구한다. 화면에는 '조건 합의 완료 · 결제 대기'라고 표시한다.
5. 양측 결제가 완료되고 유효한 슬롯 점유가 확인되면 최종 예약을 확정한다.
6. 제한시간 내 완료되지 않으면 확정 절차를 종료하고 슬롯을 해제한다. 납부한 쪽의 수수료는 전액 결제 취소를 요청한다.

사용자가 '제안대로 진행해줘'라고 승인했다. '양측 조건 합의 시 청구, 결제 후 최종 예약 확정'을 기준 정책으로 사용한다.

결제 대기 제한시간은 초기 기준 30분으로 채택한다. 업계 표준이나 PG 결제 유효시간을 뜻하지 않는다. 시설이 더 짧은 점유만 허용하면 실제 점유 만료시간을 기준으로 화면에 결제 기한을 표시하며, 시설 운영 정책 확인 후 조정한다. 외부 시설에서 슬롯 점유를 보장할 수 없으면 결제를 열기 전에 시설 확인을 완료해야 한다.

## 실패·취소 처리 제안

- 한쪽만 납부하고 기한 만료: 납부자의 수수료 전액 취소 요청, 슬롯 해제. 같은 청구로 중복 결제를 허용하지 않는다.
- 기한 종료 후 늦게 도착한 결제 성공: 종료된 예약을 자동으로 되살리지 않고 결제 취소를 요청한다.
- 양측 결제 후 시설 예약 확정 실패: 양측 취소 요청, 슬롯 해제 및 운영 알림. 한쪽 환불 실패는 별도 기록하고 재처리한다.
- 상대방 이탈 또는 시설·플랫폼 사유로 성사 실패: 피해 당사자에게 수수료 전액 환불하는 기본안을 제안한다. 이미 확정된 예약의 취소 책임과 비용은 별도 정책이다.
- 이용자의 확정 후 자발적 취소: 환불 마감과 수수료 환불 범위를 추가 결정한다. 시설 취소 비용과 플랫폼 수수료를 구분한다.
- 우천·시설 폐쇄: 시설 정책 확인 후 일정 변경 또는 환불을 처리한다.

전액 환불은 고객에게 취소 API 호출 즉시 입금된다는 뜻이 아니다. '환불 처리 중'과 실제 환불 결과를 구분해 표시한다. 수수료 선납만으로 노쇼와 서비스 외부 거래를 완전히 막을 수는 없다.

## 구현 설계에서 필요한 구분

- 조건 합의, 슬롯 임시 점유, 최종 예약 확정 상태
- 두 당사자의 독립된 청구·결제·환불 기록과 공통 적용 정책
- 서버 기준 점유 만료시간, 결제 재시도, 반복 확정 요청 처리
- 결제 결과와 예약 상태가 어긋났을 때의 취소·복구 작업
- PG 선택 및 자동 결제 지원 여부는 추후 비교 후 결정

## 남은 결정

- 시설별 임시 점유 지원과 실제 적용 가능한 제한시간
- 수수료 액수, 동일 금액 또는 동일 요율
- 야구 팀 대표 청구인지 선수별 청구인지, 골프 조인의 모집자·참가자별 청구 단위
- 상대방 없는 단독 시설 예약의 과금 방식
- 확정 후 취소·우천·노쇼 환불 기준
