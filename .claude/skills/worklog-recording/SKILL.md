# 작업 기록

## 대상 문서
- `docs/worklog.md`: 날짜별 누적 기록. 맨 아래에 `## YYYY-MM-DD — 제목` 섹션 추가.
- `docs/development-deployment-status.md`: 현재 상태 스냅숏. 덮어써도 되지만 날짜를 갱신한다.
- `docs/server-implementation-plan.md`: 단계별 완료 조건. 완료한 단계만 표시를 바꾼다.
- `README.md`: 산출물 링크가 늘었을 때만.

## worklog 섹션 형식 (기존 기록을 따른다)
```
## YYYY-MM-DD — 제목
### 승인과 구성      사용자 승인 사항
### 구현 파일        파일: 한 줄 설명
### 사용자 실행과 확인 근거
### 커밋과 배포 기록  해시: 내용
### 제약과 남은 작업
### 다음 시작점
```

## 사실 구분 규칙
기존 기록이 엄격하게 구분해 왔으므로 그대로 따른다. 근거 수준을 문장에 드러낸다.
| 근거 | 쓰는 법 |
| --- | --- |
| 사용자가 실행·화면으로 보여 줌 | "사용자 API 결과: …", "사용자 화면 NN.png: …" |
| 에이전트가 직접 실행한 명령 | 명령과 결과 요약 ("node --check 통과") |
| 작성만 하고 실행 안 함 | "작성. 적용·실행은 미확인" |
| 추정 | 쓰지 않는다. 필요하면 "확인 필요"로 남긴다 |

- 테스트·빌드·배포·SQL 적용을 실행하지 않았다면 그 사실을 명시한다.
- 비밀값, 비밀번호, 연결 문자열은 기록하지 않는다.
- 틀린 이전 기록은 지우지 않고 "정정:" 항목으로 바로잡는다.

## 입력 수집
리더가 넘긴 `_workspace/` 노트(스키마, 계약, 화면, QA 보고)에서 변경 파일, 미정 항목, 결함 처리 결과를 모은다. QA가 "미실행"으로 표시한 검증은 기록에서도 미실행이다.
