# 플레이약속 도메인 규칙

정책 원문은 `docs/requirements-draft.md`, `docs/booking-design.md`, `docs/payment-policy-proposal.md`에 있다. 이 문서는 구현 판단에 필요한 핵심만 모은다. 원문과 충돌하면 원문을 따르고 리더에게 알린다.

## 승인된 정책 (바꾸지 않는다)
- PC·모바일 브라우저 반응형 웹. 같은 계정·예약 데이터.
- 스택: Cloudflare Workers + Supabase PostgreSQL(Hyperdrive) + Supabase Auth 이메일 가입·인증 로그인.
- 시설이 공개한 슬롯을 기준으로 협의하고 약속과 시설 예약을 함께 처리한다.
- 경기 참가자 양측(시설 운영자 아님)에 같은 기준으로 수수료를 청구한다. 양측 납부 완료 후에만 최종 확정한다.
- 결제 대기 초기 기한 30분(시설 허용 시간이 더 짧으면 그 시간). 만료 시 슬롯 해제, 납부금 전액 취소 요청.

## 미정 정책 (추측해 구현하지 않는다)
수수료 금액·계산식, 개인/팀 청구 단위, 단독 대관·골프 팀 예약 과금, PG, 확정 후 취소·우천·노쇼·환불, 알림 채널, 협의 만료, 외부 시설 연동. 이 영역이 필요한 작업이면 구현을 멈추고 사용자 결정을 요청한다. 시안의 3,000원은 예시 값이다.

## 예약 상태 전이
```
Negotiating → AwaitingPayment   최신 제안 같은 버전에 양측 동의 + 슬롯 점유 + 양측 청구 (한 트랜잭션)
AwaitingPayment → Confirmed     기한 내 양측 납부 + 유효한 점유 (서버 재검사)
AwaitingPayment → Expired | Cancelled
Negotiating → Cancelled
Confirmed → Completed | CancellationRequested → Cancelled | Confirmed
```
예약 상태와 결제 상태는 따로 저장한다. 만료·취소 후 도착한 결제 성공은 예약을 되살리지 않고 환불 작업을 만든다.

## 불변식 (코드·제약·검증에서 모두 지킨다)
1. 협의 중에는 슬롯을 점유하지 않는다. 결제 대기 진입 시 임시 점유한다.
2. 활성 점유 + 확정 예약이 자원의 허용 수량을 넘지 않는다. 야구는 같은 구장 시간 겹침 금지, 골프는 티타임 판매 수량과 조인 좌석 수량을 구분한다. 검사는 슬롯이 아니라 자원 기준이다.
3. 제안은 수정하지 않고 새 버전을 만든다. 동의는 `proposal_id + version`에 연결되고, 새 버전이 생기면 이전 동의는 무효다.
4. 예약 시도당 당사자별 청구는 하나. PG 거래 식별자 중복 불가. 환불 누적액 ≤ 납부액.
5. 동의·청구·결제·취소 요청은 멱등 키로 중복 실행을 막는다.
6. 클라이언트가 보낸 금액·상태·역할을 믿지 않는다. 권한은 서버가 DB에서 확인한다.
7. 시간은 DB에 UTC(`timestamptz`), 화면은 Asia/Seoul로 표시. 만료 판단은 서버 시각 기준.
8. 채팅 메시지만으로 예약을 확정하지 않는다.
9. 확정된 예약의 시간·참가자·가격을 덮어쓰지 않는다. 변경은 별도 절차.

## 권한
| 역할 | 범위 |
| --- | --- |
| 회원 | 자신의 문의·협의·예약·청구 |
| 모집자·팀 대표 | 자신의 모집 건 |
| 시설 운영자 | `facility_operators`에 연결된 시설만 |
| 서비스 관리자 | 검수·분쟁·수수료 처리, 조치 사유 기록 |

인증 회원은 Supabase `getUser` 서버 검증 + 이메일 인증 완료가 전제다. `booking.members` 연결은 `(auth_issuer, auth_subject)` 기준.

## 운영 규칙
- 테스트 실행, `wrangler dev/deploy`, 의존성 설치, SQL 적용, 커밋·푸시는 사용자 요청이나 승인 뒤에만 한다.
- 실행하지 않은 검증을 완료로 보고하지 않는다.
- 운영 main은 시안 유지. 개발은 `development/*` 브랜치와 `book-development` Worker.
- 자격 증명은 저장소·화면·로그에 넣지 않는다. 공개 가능한 값은 `SUPABASE_URL`, `sb_publishable_` 키뿐이다.
